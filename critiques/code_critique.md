# Codebase Analysis: rms-metadata-tools

Generated by reading every file and every line of source, PDS3 label templates, cloud
configs, scripts, CI workflows, and packaging metadata in the repository (branch
`jns-updates-claude`, including uncommitted working-tree changes). Follows the
`python-codebase-analysis` skill template with project rules from `.cursor/rules/` as the
authoritative standards. This is a full fresh analysis, not a diff against the prior
report — every claim below was independently re-verified against current file contents.

**Scope note on the two large PDS3 label templates** (`templates/body_summary_columns.lbl`,
922 lines, and `templates/ring_summary_columns.lbl`, 1476 lines): these are read structurally
(OBJECT/END_OBJECT balance verified programmatically, NAME-key duplication checked) and
spot-read in full for their repeated per-column block pattern, rather than manually
re-deriving the physical correctness of all ~150 individual column descriptions. All other
files in scope, including every `.py` file and every other `.lbl` template, were read in
full, line by line.

---

## Summary

Since the prior critique cycle, eleven of its findings were fixed (encoding, the duplicate
ring tile, the `locals()` dispatch hack, the CI lint Python-version gate, the `py.typed`
comment contradiction, the `requirements.txt`/`pyproject.toml` TODO, etc. — see
"Findings resolved since the last cycle" below). This fresh pass found **six new
correctness bugs that were not caught previously**, three of them significant enough to
affect production output:

1. **`create_cumulative_indexes()` silently ignores the host's `exclude` list and the
   `--exclude` CLI flag everywhere except the one call site that happens to pass it
   explicitly** (`cumulative_support.py`) — the cloud/worker cumulative path never applies
   the configured exclusion, and even the local `--exclude` flag is parsed and discarded.
2. **A dead `prefix` constructor parameter** on `common.Table.__init__` that is assigned
   from the caller's argument and then unconditionally overwritten before it is ever read —
   any caller passing `prefix=` has that value silently discarded.
3. **A truthy-vs-`is None` bug in the "unused columns" accumulator** in
   `index_support/process.py` that resets tracking to a single volume's results instead of
   keeping the running intersection once it legitimately becomes empty, corrupting the
   final "Unused columns" warning on multi-volume runs.
4. **The target-name translation mechanism (`defs._translations`) is completely unwired** —
   `set_translations()` is never called anywhere in the codebase, so the lookup in
   `record.py` is permanently dead code.
5. **`geometry_config.target_name()`'s docstring describes SKY-target resolution logic that
   the one-line implementation does not perform** — either lost functionality or a stale
   docstring.
6. **`key__on_chip_mosaic_flag()` returns `'Y'` for the SL9 override**, contradicting the
   published label's own `'YES'`/`'NO'` value domain for that column.

Two additional data-quality issues were found in the shipped PDS3 label templates
(a stray comma and a missing word, both in customer-facing `DESCRIPTION` text), and a
confirmed repo-hygiene bug: three `metadata-*.db` job-state files are tracked in git
despite a `.gitignore` pattern that should exclude them (the pattern was added after the
files were already tracked, so it has no effect — `git rm --cached` is required).

### 1.4 — Duplicated terminator-normalization logic between `write_txt_file` and `append_txt_file` [LOW]

**Evidence**: `src/metadata_tools/util.py:365-395` (`write_txt_file`) and `:398-435`
(`append_txt_file`) both contain the identical 10-line block:
```python
    if terminator is None:
        if isinstance(content, list):
            crlf = content[0].endswith('\r\n')
        else:
            crlf = content.endswith('\r\n')
        terminator = '\r\n' if crlf else '\n'

    lines = content.split('\n') if not isinstance(content, list) else content
    lines = [c.rstrip('\r\n') for c in lines]

    text = terminator.join(lines) + terminator
```

**Self-contained fix**: Extract a private helper in `util.py`:
```python
def _normalize_text(content: str | list[str], terminator: str | None) -> str:
    if terminator is None:
        crlf = (content[0] if isinstance(content, list) else content).endswith('\r\n')
        terminator = '\r\n' if crlf else '\n'
    lines = content.split('\n') if not isinstance(content, list) else content
    lines = [c.rstrip('\r\n') for c in lines]
    return terminator.join(lines) + terminator
```
Then have both `write_txt_file` and `append_txt_file` call `text = _normalize_text(content,
terminator)` and keep only their distinct final I/O step (`path.write_text(text, ...)` vs.
the read-then-concatenate-then-write pattern already in `append_txt_file`).

## 2. Best Practices Alignment

### 2.1 — `--new_only`/`-n` accepts volume names it silently discards [MEDIUM]

**Rule**: `python.mdc` — CLI arguments should do what their signature promises; a
`nargs='*'` argument that accepts values and then ignores them is a correctness/usability
defect, not merely a style nit.

**Evidence**: `src/metadata_tools/geometry_support/process.py:45-47`:
```python
    gr.add_argument('--new_only', '-n', nargs='*', type=str, metavar='new_only',
                    default=False,
                    help='''Only volumes that contain no output files are processed.''')
```
`process_tables()` then only ever checks `new_only = args.new_only is not False` (line 90)
and `if new_only and any(outdir.glob('*_inventory.csv')):` (line 136, inside the per-volume
walk). No code path reads the actual list of volume names a user might pass, e.g.
`--new_only GO_0017 GO_0018`. The user guide
(`docs/user_guide/user_guide_geometry.rst:74`) documents `--new_only [VOL ...]` with the
same `[VOL ...]` signature, without promising the values do anything — but nothing warns
the user that supplying them has zero effect.

**Self-contained fix**: Either (a) change the flag to a pure boolean toggle —
`gr.add_argument('--new_only', '-n', action='store_true', help='...')` and change
`new_only = args.new_only is not False` to `new_only = args.new_only` — or (b) if the
intent was to let users restrict the "already processed" check to specific volumes,
thread `args.new_only` (when it's a non-empty list) into the per-volume skip condition,
e.g. `if new_only and (not args.new_only or vol in args.new_only) and
any(outdir.glob('*_inventory.csv')):`. Option (a) is the smaller, safer change since no
existing caller relies on volume-scoped behavior (confirmed via
`grep -rn new_only src/ docs/ tests/`).

## 6. Maintainability and Extensibility

### 6.1 — `create_cumulative_indexes()` ignores the `exclude` argument in the worker/cloud path, and ignores the `--exclude` CLI flag everywhere [CRITICAL]

**Evidence**: `src/metadata_tools/cumulative_support.py:137-183`:
```python
def create_cumulative_indexes(template_name: str,
                              volumes: list[str] | None = None,
                              args: argparse.Namespace | None = None,
                              exclude: list[str] | None = None) -> None:
    ...
    if not args:
        parser = get_args(host=host, exclude=exclude)
        args = parser.parse_args()
    ...
    for table in tables:
        _cat_rows(volume_tree, cumulative_dir, template_path, volume_glob,
                  table, exclude=exclude, volumes=volumes)
```
`_cat_rows()` is always called with the function's own `exclude` **parameter** — never
with `args.exclude`, even though `args.exclude` is exactly what the `--exclude` CLI flag
populates (via `get_args()`'s `gr.add_argument('--exclude', ...)` at
`cumulative_support.py:129-131`). This means:

1. **Local (`metadata-cumulative`)**: `cli/cumulative.py:27` calls
   `cml.create_cumulative_indexes(hconf.template_name, exclude=config.exclude)` — no
   `args=` is passed, so the function parses `sys.argv` internally into `args`, but then
   *ignores* `args.exclude` and always uses the `exclude=config.exclude` value the caller
   supplied. **A user who runs `metadata-cumulative GO_0xxx ... --exclude GO_0016` will
   see `GO_0016` parsed into `args.exclude` and then thrown away** — only the host's
   hardcoded default (`['GO_0999']`) is ever honored.
2. **Worker/cloud (`metadata-cumulative-worker`, `metadata-cumulative-cloud`)**:
   `cli/cumulative_worker.py:39-40`'s `_CumulativeTask.__call__` calls
   `create_cumulative_indexes(self._template_name, args=worker_data.args)` — **no
   `exclude=` argument at all**, so it defaults to `None`. **The host's configured
   `exclude` list (`geometry_config.exclude = ['GO_0999']`) is never applied when running
   via the worker or GCP dispatch path.** For GO_0xxx today this happens to be masked
   because `_cat_rows()` independently skips the cumulative output directory by name
   (`cumulative_support.py:58`: `if cumulative_dir.name in root.as_posix(): continue`),
   but for any future host whose `exclude` list contains volumes *other than* the
   cumulative directory itself (e.g. known-bad or superseded volumes), the worker/cloud
   path will silently include them while the local path (correctly, via the hardcoded
   default) excludes them — a cross-path data inconsistency.

**Self-contained fix**: In `src/metadata_tools/cumulative_support.py`,
`create_cumulative_indexes()`, change the loop to prefer `args.exclude` when it was
supplied on the command line, falling back to the `exclude` parameter (the host default)
otherwise:
```python
def create_cumulative_indexes(template_name: str,
                              volumes: list[str] | None = None,
                              args: argparse.Namespace | None = None,
                              exclude: list[str] | None = None) -> None:
    host, _index_type, template_dir = util.parse_template_name(template_name)
    template_path = template_dir / FCPath(template_name).with_suffix('.lbl')

    if not args:
        parser = get_args(host=host, exclude=exclude)
        args = parser.parse_args()

    if not volumes:
        volumes = args.volumes

    effective_exclude = args.exclude if getattr(args, 'exclude', None) is not None else exclude
    ...
    for table in tables:
        _cat_rows(volume_tree, cumulative_dir, template_path, volume_glob,
                  table, exclude=effective_exclude, volumes=volumes)
```
Then, in `src/metadata_tools/cli/cumulative_worker.py`, pass the host's default explicitly
so the worker path matches the local path:
```python
class _CumulativeTask:
    def __init__(self, host_id: str, template_name: str, exclude: list[str] | None) -> None:
        self._host_id = host_id
        self._template_name = template_name
        self._exclude = exclude

    def __call__(self, _task_id, task_data, worker_data):
        set_host(self._host_id)
        from metadata_tools.cumulative_support import create_cumulative_indexes
        create_cumulative_indexes(self._template_name, args=worker_data.args,
                                  exclude=self._exclude)
        return False, None
```
and in `main()`, construct it as `_CumulativeTask(host_id, hconf.template_name,
get_geometry_config().exclude)` (this requires calling `get_geometry_config()` in
`cumulative_worker.py`'s `main()`, which reintroduces the SPICE-init cost the lazy-loading
change in `config.py` was designed to avoid for the worker path — if that tradeoff is
unacceptable, instead move `exclude` into `host_config.py` as a host-agnostic setting
so it can be read without loading `geometry_config`). Add the regression test described
in finding 4.2.

### 6.2 — `defs._translations` / `set_translations()` is completely unwired dead code [HIGH]

**Evidence**: `src/metadata_tools/defs.py:34-46` defines `_translations` and a
`set_translations()` setter:

_translations: dict[str, str] = {}
"""Maps raw target names to canonical body names. Set via :func:`set_translations`."""

def set_translations(mapping: dict[str, str]) -> None:

It is read in `src/metadata_tools/geometry_support/record.py:75-76`:

If no remapping is currently needed, remove `_translations`, `set_translations()`, and the
`record.py:75-76` lookup entirely, and note in a commit message or issue that the

### 6.3 — `geometry_config.target_name()` docstring describes logic the implementation does not have [HIGH]

**Evidence**: `src/metadata_tools/hosts/GO_0xxx/geometry_config.py:196-209`:
```python
def target_name(snapshot: dict[str, Any]) -> str:
    """Determine the target name from the snapshot's dictionary.

    If the given name is "SKY", it checks the CIMS ID and the TARGET_DESC for
    something different.

    Parameters:
        snapshot: Snapshot observation dictionary.

    Returns:
        Target name.
    """

    return cast(str, snapshot["TARGET_NAME"])
```
The docstring's second paragraph describes special-case handling for `TARGET_NAME ==
"SKY"` (checking `CIMS ID` and `TARGET_DESC` fields for a more specific target), but the
function body is an unconditional one-line passthrough of `snapshot["TARGET_NAME"]`. There
is no conditional logic, no reference to `CIMS ID` or `TARGET_DESC` anywhere in this
function or file. This means either (a) this logic existed previously and was
accidentally deleted in a refactor, silently changing behavior for any GO_0xxx observation
whose `TARGET_NAME` is literally `"SKY"` (such images would now carry `target = "SKY"`
downstream, which is not a valid `oops.Body` name, so `bodies_select.select_bodies()`'s
`oops.Body.exists(record.target)` check at `record.py:112` would evaluate `False` and skip
target/parent-system inclusion for those observations), or (b) the docstring is simply

### 6.5 — `_create_index()`'s unused-columns accumulator resets instead of staying empty once every column has been used somewhere [HIGH]

**Evidence**: `src/metadata_tools/index_support/process.py:83-118`:
```python

    unused: set[str] | None = None
    ...

        ...

```
The intent is clearly to track the **intersection** of "columns unused in this volume"
across all processed volumes, so the final warning lists only columns that were unused in
*every* volume. `unused = index.unused if not unused else unused & index.unused` uses a

empty (meaning every column has been used in at least one volume seen so far, which is the
*correct*, desired end state), the **next** volume's iteration re-triggers the `not
unused` branch and **overwrites** the accumulator with that single volume's unused set,
discarding the fact that other columns were already proven "used somewhere." For a
multi-volume run (this is the normal case — GO_0xxx has volumes GO_0002 through GO_0023),
this means the final "Unused columns" warning can incorrectly list columns that a
mid-run volume did use, purely because the accumulator's empty-state was misread as
"uninitialized."

**Self-contained fix**: In `src/metadata_tools/index_support/process.py`, replace the
truthy check with an explicit `is None` check:
```python
                index.create(labels_only=labels_only, pattern=pattern)
                unused = index.unused if unused is None else unused & index.unused
```
Add a regression test in `tests/test_index_support.py` (or wherever `_create_index()` is
tested) covering three volumes where: volume 1 leaves column `A` unused, volume 2 uses
column `A` but leaves column `B` unused, and volume 3 uses both — assert the final
`logger.warning` call (via `caplog`) is either not made at all, or is made with an empty
set — not with `{'A'}` (the bug's incorrect output) or `{'B'}`.

### 7.2 — `IndexTable._get_null_value()` uses a truthy check instead of `is not None`, so a legitimate `0` null constant is skipped [MEDIUM]

**Evidence**: `src/metadata_tools/index_support/table.py:288-313`:
```python
    @staticmethod
    def _get_null_value(pds3_table: Pds3Table, colnum: int) -> Any:
        nullkeys = ['NULL_CONSTANT',
                    'UNKNOWN_CONSTANT',
                    'INVALID_CONSTANT',
                    'MISSING_CONSTANT',
                    'NOT_APPLICABLE_CONSTANT']

        nullval = None
        for key in nullkeys:
            if nullval := pds3_table.old_lookup(key, colnum):
                break

        return nullval
```
`if nullval := pds3_table.old_lookup(key, colnum):` treats any falsy lookup result the
same as "not found," not just `None`. Several columns in this codebase's own templates use
integer null constants that are falsy when zero-like or empty-string, e.g.
`NOT_APPLICABLE_CONSTANT = -1` for `CUT_OUT_WINDOW`/`TRUTH_WINDOW`/`ICT_DESPIKE_THRESHOLD`
(non-zero, unaffected) but `PRODUCT_VERSION_ID`'s `NOT_APPLICABLE_CONSTANT = 0`
(`GO_0xxx_supplemental_index.lbl:161`) **is** falsy. For that column, if `old_lookup`
returns the integer `0` for `NOT_APPLICABLE_CONSTANT`, the walrus check
`if nullval := 0:` is `False`, so the loop does **not** break and instead continues to the
next key (`MISSING_CONSTANT`), most likely finding nothing and leaving `nullval = None`.
Downstream, `_index_one_value()` (`table.py:249-250`) treats a `None` null constant as a
hard error: `raise ValueError('Null constant needed for %s.' % column_stub['NAME'])` —
meaning any label whose `PRODUCT_VERSION_ID` is genuinely absent (triggering the null path)
would crash the whole index run instead of writing the intended `0`.

**Self-contained fix**: In `src/metadata_tools/index_support/table.py`, change the
walrus-based loop to check for `None` explicitly and stop at the first key that is
*present* (including falsy present values), not merely "truthy":
```python
        nullval = None
        for key in nullkeys:
            candidate = pds3_table.old_lookup(key, colnum)
            if candidate is not None:
                nullval = candidate
                break

        return nullval
```
Confirm `pds3_table.old_lookup()`'s actual "not present" sentinel (check the
`rms-pdstemplate`/`Pds3Table` source or its docs — it may return `None`, raise `KeyError`,
or return some other sentinel) and adjust the `is not None` check accordingly if it
differs. Add a test in `tests/test_index_support.py` covering a column whose
`NOT_APPLICABLE_CONSTANT` is `0`.
